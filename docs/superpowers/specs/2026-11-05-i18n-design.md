# 다국어(한국어·영어) 설계

## 배경 / 목표

새 탭 화면의 문구가 전부 한국어로 코드에 직접 쓰여 있다(주석 제외 약 440줄, `apps/extension`·`packages/ui`·`packages/core`의 80여 파일). 스토어에 공개된 확장을 영어권 사용자도 쓸 수 있게 **한국어·영어** 두 언어를 지원한다.

설정 화면 위치는 시안(`docs/design/language-switch.html`)에서 D안으로 정했다. 이 문서는 시안 없이도 구현할 수 있게 그 결과를 옮겨 적는다.

## 정한 것

사용자가 고른 것:

- 언어는 **한국어·영어 두 가지만**.
- 처음엔 **브라우저 언어를 자동으로 따르고**, 설정에서 바꿀 수 있다.
- 바꾼 언어는 **이 기기에만** 저장한다(계정 동기화 없음, DB 변경 없음).
- 구현은 **자체 사전**(라이브러리 없이 `ko`·`en` 객체). 언어를 바꾸면 **새로고침 없이 바로** 화면이 바뀐다.
- 첫 화면 깜빡임이 없도록 저장 위치는 동기로 읽는 `localStorage`(테마 캐시와 같은 방식).
- 시스템이 한국어로 자동 저장하던 데이터: 만드는 순간의 언어로 저장한다. 단, DB 트리거가 만드는 개인 조직 이름 `'개인'`만은 화면에 보일 때 번역한다(3절).
- 로그인 화면: 문구는 번역하고, 언어 전환 버튼은 두지 않는다(브라우저 언어 규칙으로만 정해짐).
- 전환 위치(D안): 레일의 **테마 줄을 톱니 '설정'으로** 바꾸고, 설정 패널 **맨 위에 언어**, 그 아래에 테마.

제 제안을 사용자가 받아들인 것:

- React Context 대신 **모듈 하나에 현재 언어를 두고 화면이 구독**한다(`useSyncExternalStore`). 사용자에게 보이는 동작은 Context와 같고, React 밖 코드도 같은 사전을 읽을 수 있다.
- 브라우저 언어 판단: 선호 언어 목록을 앞에서부터 보고 한국어·영어 중 먼저 나오는 것, 둘 다 없으면 영어.
- `packages/core`는 사전을 모른다. 문구 대신 오류 코드를 던지거나 호출하는 쪽이 번역된 값을 넘긴다.

제 판단으로 정한 것(사용자가 따로 정하지 않음):

- 언어 이름은 늘 그 언어로 쓴다: `한국어` / `English` (번역하지 않음).
- 영어 문구는 구현하면서 제가 쓰고, PR에서 확인받는다.
- 코드 주석은 번역하지 않는다.

## 1. 사전과 언어 상태

위치: `packages/ui/src/i18n/`. `ui`와 `extension` 두 패키지의 문구를 한 사전에 담는다(`extension`은 이미 `@tablign/ui`에 의존).

| 파일 | 내용 |
|---|---|
| `ko.ts` | 한국어 사전. 타입의 기준(`export type Messages = typeof ko`). |
| `en.ts` | 영어 사전. `export const en: Messages` — 키가 빠지거나 모양이 다르면 `tsc`가 실패한다. |
| `index.ts` | 언어 상태와 훅. 아래 API. |

사전 모양:

- 화면 영역별로 묶은 중첩 객체: `t.rail.settings`, `t.settings.language`, `t.collection.deleted(title)` 등.
- 값은 **문자열** 또는 **문자열을 돌려주는 함수**만. 숫자·이름이 끼는 문구는 함수(`(n: number) => ...`)로 쓰고, 영어 복수형도 함수 안에서 처리한다.
- 줄바꿈이 있는 문구(예: 로그인 제목 "탭을 정렬하는<br/>가장 단정한 방법.")는 `\n`으로 쓰고 그리는 쪽에서 `whiteSpace: "pre-line"`.

API (`@tablign/ui`에서 내보냄):

```ts
type Locale = "ko" | "en";
detectLocale(stored: string | null, languages: readonly string[]): Locale  // 순수 함수
getLocale(): Locale
setLocale(l: Locale): void   // 저장 + <html lang> 갱신 + 구독자 알림
getT(): Messages             // React 밖에서, 부르는 순간의 언어
useT(): Messages             // 컴포넌트용 — 언어가 바뀌면 다시 그림
useLocale(): Locale
```

- 저장 키: `localStorage["tablign.locale"]` (테마의 `tablign.theme`와 같은 규칙). 값이 `"ko"`·`"en"`이 아니면 없는 것으로 본다. 읽기·쓰기는 `try/catch`로 감싸고, 막혀 있으면 브라우저 언어로 계속 그린다.
- 판단 순서: 저장된 값 → `navigator.languages`(없으면 `[navigator.language]`)를 앞에서부터 보며 `ko`·`en`으로 시작하는 첫 값 → `"en"`.
- 모듈을 불러오는 순간 동기로 언어를 정하고 `document.documentElement.lang`을 맞춘다. 그래서 첫 렌더부터 맞는 언어로 그린다.
- `useT`·`useLocale`은 `useSyncExternalStore(subscribe, getLocale)`로 구독한다. Provider로 감쌀 필요가 없다.

## 2. 문구 옮기기

**대상**: `apps/extension/src`, `packages/ui/src`의 화면 문구 전부. 버튼·메뉴·토스트·확인창·빈 화면, 화면에 안 보이는 `title`·`aria-label`도 포함. 로그인 화면(`AuthScreen.tsx`)도 포함하며, 왼쪽 제품 미리보기 속 예시 이름(개인·업무·리서치, 읽을거리 등)도 번역한다.

**컴포넌트**: 한국어 리터럴을 `const t = useT()` 후 `t.xxx`로 바꾼다.

**React 밖 코드**: 부르는 순간 `getT()`로 읽는다.
- `apps/extension/src/lib/oauth.ts` 로그인 오류 문구
- `apps/extension/src/lib/tabs.ts` "브라우저 내부 페이지는 담을 수 없어요"
- `apps/extension/src/lib/backgroundPhoto.ts` 오류 문구

**모듈 상수에 든 이름표**: 상수에는 id만 남기고, 그릴 때 사전에서 찾는다. 모듈을 불러올 때 굳어 버리면 언어를 바꿔도 안 바뀌기 때문이다.
- `themeSettings.ts`의 강조색 이름(`ACCENT_PRESETS[].name`)·사진 예시 이름(`SAMPLE_PHOTOS[].name`)
- `ThemePanel.tsx`의 `MODES`·`KINDS` 이름표
- `tossEmoji.ts`의 이모지 분류 이름

**`packages/core`의 문구 2개**:
- `import/toby.ts`의 "Toby 내보내기 파일이 아니에요" → 영어 메시지(`Not a Toby export file`)로 바꾼다. 화면은 이 메시지를 쓰지 않고(`NewTab.tsx`의 `pickTobySource`가 오류를 잡아 `importAlert = "invalid"` 알림을 따로 띄움) 개발자용으로만 남기 때문이다. (계획 단계에서 코드를 읽고 오류 클래스안 대신 고침.)
- `import/plan.ts`의 `SHARED_COLLECTION_TITLE = "공유 폴더"` → 상수를 없애고, 계획을 만드는 함수가 제목을 인자로 받는다. 호출하는 쪽이 `t.import.sharedCollection`을 넘긴다.

**날짜**: 화면에 보이는 날짜(공유 코드 만료일 등)는 `toLocaleDateString(getLocale())`. 내보내기 파일 이름의 날짜(`sv-SE` → `2026-11-05`)는 언어와 상관없는 형식이라 그대로 둔다.

**그대로 두는 것**: 이모지 검색(이미 영어 키워드), Supabase가 돌려주는 서버 오류 원문, 사용자가 입력한 이름.

## 3. 시스템이 저장하는 데이터

사용자가 입력하지 않았는데 한국어로 저장되던 값:

| # | 값 | 생기는 때 | 위치 | 처리 |
|---|---|---|---|---|
| 1 | 조직 `'개인'` | 가입 시 DB 트리거 | `0015_spaces_org.sql:44` | **표시할 때 번역** |
| 2 | 스페이스 `'개인'` | 스페이스가 없을 때 컬렉션 만들기·창 담기 | `NewTab.tsx:636`, `:916` | 만드는 순간 언어로 저장 |
| 3 | 컬렉션 `'새 컬렉션'` | 컬렉션 추가 | `NewTab.tsx:641` | 만드는 순간 언어로 저장 |
| 4 | 컬렉션 `'창 N'` | 열린 창을 컬렉션으로 담기 | `NewTab.tsx:952`, `:1013` | 만드는 순간 언어로 저장 |
| 5 | 컬렉션 `'공유 폴더'` | 북마크 가져오기 | `plan.ts:10` | 만드는 순간 언어로 저장 |

이미 저장된 값은 바꾸지 않는다. `'새 조직'`(`NewTab.tsx:438`)은 이름이 비면 만들기 버튼이 꺼져(`OrgFormDialog.tsx:446`) 실제로 저장되지 않으므로 그대로 둔다.

**1번 표시 규칙** — `orgDisplayName(org, t)`:
- `org.is_personal`이고 `org.name === "개인"`이면 `t.org.personal`("개인" / "Personal").
- 그 밖에는 `org.name` 그대로(프로필 설정에서 이름을 바꾼 경우).

쓰는 곳: 조직 레일(지금은 `"개인"`을 코드에 직접 씀 → 이름을 바꿔도 레일엔 "개인"으로 나오던 것도 함께 맞춰짐), 조직 머리(`OrgHeader`), 프로필 설정 폼의 처음 이름, 내보내기 파일 이름.

## 4. 설정 패널 (D안)

**레일** (`OrgRail.tsx`):
- 테마 줄의 아이콘을 팔레트 → **톱니**(lucide `Settings`, `@tablign/ui` 아이콘 목록에 추가), 이름을 **설정**으로. `aria-label`도 설정.
- 열림 표시(막대 + 옅은 강조색 상자)는 지금 테마 줄과 같다.
- prop 이름도 `themeOpen`·`onToggleTheme` → `settingsOpen`·`onToggleSettings`.

**오른쪽 패널** (`NewTab.tsx`의 `RightDrawer`, `label="설정"`):
- 머리: 강조색 채움, 톱니 아이콘, **설정**, 닫기(`설정 닫기`). 지금 테마 패널 머리 모양 그대로.
- **언어** 묶음: `Segmented`로 `한국어 | English`. 누르면 `setLocale` — 바로 바뀌고 서버에는 아무것도 보내지 않는다.
- 구분선
- **테마** 묶음: 지금 테마 패널의 내용(모드·강조색·배경·투명도·기본으로 되돌리기) 그대로. '기본으로 되돌리기'는 테마만 되돌린다.
- 묶음 제목(언어·테마): 13px, 굵기 740, 본문 색. 그 안의 섹션 이름(모드·강조색·배경)은 지금처럼 11.5px 흐린 색.
- 패널 너비 저장(`panels.themeWidth`)·열고 닫는 동작은 그대로.
- UI 안에 안내 문구를 넣지 않는다.

구성: `ThemePanel`은 자기 머리를 빼고 테마 묶음 내용만 그린다. 새 `SettingsPanel`이 머리 + 언어 묶음 + `ThemePanel`을 감싼다.

## 5. 매니페스트·HTML

- `apps/extension/public/_locales/ko/messages.json`, `_locales/en/messages.json`에 `appDesc`:
  - ko: `시각적 북마크·탭 관리` (지금 값)
  - en: `Visual bookmark & tab manager`
- `manifest.json`: `"default_locale": "en"`, `"description": "__MSG_appDesc__"`. 이름 `tablign`은 그대로.
- 이 부분은 Chrome이 **Chrome 자체 언어**로 고른다(앱 안 언어 설정과 무관). 확장 관리 페이지·스토어에 보이는 설명이다.
- `newtab.html`의 `<html lang="ko">`는 그대로 두고, 1절의 모듈이 시작할 때 맞는 값으로 덮어쓴다.

## 6. 테스트

- 기존 테스트 약 1,755줄이 한국어 문구로 요소를 찾는다. jsdom의 브라우저 언어는 `en-US`이므로, `apps/extension/src/test-setup.ts`와 `packages/ui/src/__tests__/setup.ts`에서 `setLocale("ko")`로 고정한다. 문구를 사전으로 옮기는 것만으로는 기존 테스트를 고치지 않아도 통과해야 한다.
- 고치는 기존 테스트는 동작이 바뀐 곳뿐: 4절의 테마→설정 이름 변경(`OrgRail.test.tsx`, `ThemePanel.test.tsx` 등), `packages/core`의 제목 인자 변경.
- 새 테스트:
  - `detectLocale`: 저장값 우선, 저장값이 이상하면 무시, `languages` 순서(`["en-US","ko"]` → en, `["ja","ko-KR"]` → ko), 둘 다 없으면 en.
  - `setLocale` 후 `useT`를 쓰는 컴포넌트가 다시 그려지고, `localStorage`·`<html lang>`이 바뀐다.
  - `orgDisplayName`: 개인 + `'개인'` → 사전 값, 개인 + 바꾼 이름 → 그대로, 팀 조직 → 그대로.
  - 설정 패널: `English`를 누르면 패널 문구가 영어로 바뀐다.
  - 영어 화면 확인 하나: 로그인 화면을 `en`으로 그려 "Continue with Google"이 보인다.
- 빠진 영어 번역은 테스트가 아니라 `tsc`(`pnpm lint`)가 잡는다.
