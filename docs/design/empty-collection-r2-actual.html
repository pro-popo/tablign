R2 빈 상태 — 실측 1:1

실제 치수로 다시 그렸습니다: 조직 레일 54 + 좌 패널 212 + 우 패널 272 = 538px, 보드 padding 16px 18px. 1440 화면에서 보드 내부가 866px입니다 (usePanelState.ts:13, Board.tsx:8).
앞선 시안의 보드는 324px이었으니 2.7배 차이입니다 — 카드 크기 판단이 완전히 달라집니다. 글자 크기도 모두 실측값(보드 제목 15px, 스페이스 행 14px, 탭 행 13px)으로 맞췄습니다.

1. 1440 × 900 · 앞선 시안의 카드 폭(300px)을 그대로 확대

보드 내부 866px · 카드 300px → 좌우 여백 각 283px

이게 문제입니다. 866px 보드 한가운데 300px 카드가 놓이면 좌우 여백이 카드보다 넓어서 화면이 미완성처럼 보입니다. 작은 시안에서는 카드가 보드를 꽉 채웠기 때문에 보이지 않던 결함이에요.

2. 같은 화면 · 카드 폭 400px + 미리보기를 실제 탭 행으로

보드 내부 866px · 카드 400px · 미리보기 = 탭 3행 + “＋2개 더”

400px에서는 파비콘 옆에 실제 탭 제목이 들어갑니다. 가로 칩 5개는 각 칸이 69px여서 제목을 못 넣고 회색 바로 남았는데, 세로 3행은 “무엇이 담기는지”를 글자로 보여줍니다 — R2를 고른 이유가 여기서 제대로 살아납니다. 오른쪽 패널의 하이라이트된 탭 목록과 카드 안 목록이 같은 것이라는 게 한눈에 읽혀요.

3. 엣지 케이스 — 보드 영역만 실측 크롭

폭·글자 크기는 위와 동일한 실측값입니다. 세로만 300px로 잘랐습니다.

3-1. 탭이 1개뿐일 때

가로 칩 방식이면 칸 4개가 비어 깨진 그리드가 됩니다. 세로 행 방식은 1행이면 1행이라 자연스럽습니다. 문구도 “지금 창의 탭 1개 담기”로 수가 그대로 흘러갑니다.

3-2. 탭이 24개일 때

3행 + “＋21개 더”로 고정. 카드 높이가 탭 수에 따라 변하지 않는 게 중요합니다.

3-3. 우측 패널을 접었을 때 (보드 1138px)

보드가 1138px로 더 넓어지지만 카드는 400px 고정 + 중앙 정렬이라 레이아웃이 안 무너집니다. 다만 미리보기의 근거인 “열린 탭 패널”이 화면에서 사라진 상태라, 카드 안 목록이 유일한 단서가 됩니다 — 세로 행 방식이 여기서 더 유리합니다.

3-4. 1152 좁은 창 + 멤버·초대 버튼까지 있는 헤더

보드 내부 578px. 카드 400px이 여전히 편안하고, 헤더 버튼이 늘어도 ＋ 컬렉션 split이 밀리지 않습니다. 좌·우 패널을 최대(400)까지 늘린 최악 조건에서도 보드는 1152−54−800−36 = 262px이므로, 카드에 max-width:400px; width:100%를 주면 그때만 줄어듭니다.

4. 실측에서 나온 조정 사항

  1. 카드 폭 300 → 400px. 866px 보드에서 300px은 너무 작습니다. width:100%; max-width:400px로 두면 패널을 최대로 넓힌 최악 조건(보드 262px)에서도 안전합니다.
  2. 미리보기: 가로 칩 → 세로 탭 행 3개 + “＋N개 더”. 가로 칩은 칸이 69px로 좁아 제목이 안 들어가고, 탭이 1~2개면 빈 칸이 남습니다. 세로 행은 두 문제가 동시에 사라지고 정보량이 늘어납니다.
  3. 헤드라인 17px / 서브 13px. 작은 시안의 13.5px을 그대로 쓰면 15px인 보드 제목보다 작아져 위계가 뒤집힙니다. SpaceOnboarding의 19px보다는 한 단 낮춰 온보딩이 두 번 나오는 느낌을 피했습니다.
  4. 아이콘 박스 28 → 34px. 14px 제목 옆에서 28px은 눌려 보입니다.
  5. “＋N개 더” 문구는 카드 안에 두기. 카드 밖 캡션(“창 1의 탭이 이대로 담겨요”)은 실측에서 군더더기로 읽혀 지웠습니다 — 카드 제목이 이미 “지금 창의 탭 5개 담기”라고 말합니다.
