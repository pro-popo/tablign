Chrome 북마크 가져오기 — 폴더 매핑을 사용자가 직접 지정하는 설정 UI

tablign은 스페이스 → 컬렉션 → 링크 3단인데 Chrome 북마크는 폴더가 임의 깊이로 중첩된다. 그래서 설정 UI가 답해야 하는 질문은 세 개다 — ① 어떤 폴더를 가져올지, ② 어떤 폴더가 스페이스인지, ③ 깊이가 안 맞는 폴더는 어떻게 처리할지.

세 시안 모두 아래 같은 북마크 트리를 쓴다 — 깊이 3단(개발 › React › Hooks), 하위 폴더 없이 링크만 든 1단 폴더(뉴스, 나중에 읽기), 하위 폴더와 링크가 섞인 폴더(개발), 폴더에 안 담긴 루트 직속 링크, 여러 폴더에 중복으로 들어간 URL까지 실제로 흔한 형태를 넣었다. B안은 체크박스가 실제로 동작해서 오른쪽 결과가 바뀐다.

정한 규칙1단 폴더는 무조건 스페이스 · 중복 URL 제거

앞선 논의에서 갈렸던 두 지점을 이렇게 정했다. 아래 세 시안은 모두 이 규칙을 적용한 상태다.

규칙 ①1단 폴더 = 스페이스, 직속 링크는 공유 폴더로

1단 폴더는 하위 폴더가 있든 없든 모두 스페이스가 된다. 스페이스는 링크를 직접 담을 수 없으니, 폴더에 직접 들어있던 링크만 모아 공유 폴더라는 컬렉션 하나로 넣는다. 뉴스처럼 하위 폴더가 아예 없는 폴더는 공유 폴더 하나만 갖는다.

규칙 ②같은 URL은 한 번만 담는다

여러 폴더에 같은 링크를 넣어둔 경우, 트리 순서상 처음 만난 것만 남기고 나머지는 버린다. Chrome 북마크는 원본이 그대로 남으니 잃는 건 없다. 빠진 개수는 미리보기와 푸터에 숫자로 드러낸다 — 조용히 사라지면 안 된다.

공통으로 정해둔 기본값

시안 세 개가 모두 같은 전제를 깔고 있다. 이 기본값이 맞는지도 같이 봐주세요.
  • 1단 폴더 = 스페이스. 하위 폴더가 있든 없든 똑같이 적용한다. 사용자는 "고치는" 것만 한다 — 백지에서 지정하지 않는다.
  • 폴더에 직접 들어있던 링크는 공유 폴더 컬렉션으로 모인다. 직속 링크가 0개면 만들지 않는다.
  • 루트 직속 링크(폴더에 안 담긴 것)는 북마크바 스페이스의 공유 폴더가 된다.
  • 3단 이하 폴더는 부모/자식 이름으로 합쳐 컬렉션이 된다. 폴더가 사라지지도, 컬렉션이 폭발하지도 않는다.
  • 같은 URL은 한 번만. 트리 순서상 처음 만난 것만 남긴다. 빠진 개수는 컬렉션마다 −n으로 드러낸다.
  • 링크 100개 넘는 폴더는 기본 해제. 대개 "나중에 읽기" 같은 묘지라서, 켜면 첫 보드가 못 쓰게 된다.
  • 빈 폴더는 트리에 아예 안 보인다(링크 0개 + 하위 폴더 0개).
  • 가져와도 Chrome 북마크는 그대로 남는다. 지우거나 옮기지 않는다 — 복사만.

아직 안 정한 것

  • 공유 폴더라는 이름. tablign엔 이미 공유(공유 코드·공유 스페이스·조직)가 있어서 "이 컬렉션은 공유된 것"으로 읽힐 수 있다. 후보: 모아둔 링크, 기타, 폴더이름 그대로.
  • URL 정규화 수준. ?utm_source=·끝의 /·http↔https까지 같게 볼지. 세게 하면 의도적으로 다르게 저장한 링크까지 합쳐진다.
  • 4단 이상 폴더. 부모/자식만 붙이면 서로 다른 경로의 A/B가 충돌할 수 있다 (경로 전체를 쓸지, 번호를 붙일지).
  • 가져오기 후 되돌리기. 스페이스 5개가 한 번에 생기는데, 마음에 안 들면 하나씩 지워야 한다 — "이번 가져오기 취소" 같은 되돌리기를 줄지.
